# Repository Authority Adoption

## Purpose

This document records how BHG-Ecosystem-Foundation participates in the cross-repository authority sequence during normalization.

It is a draft adoption artifact and does not create authority above the repository's approved Foundation scope.

## Authority position

BHG-Ecosystem-Foundation is a foundational domain repository. It owns institutional and ecosystem architecture within its approved scope.

It does not become an independent constitutional root and does not supersede BHG-wide governance.

## Required sequence for new documents

Before creating a normative or architectural document in this repository:

1. Identify the applicable BHG constitutional and foundational authority.
2. Identify the applicable BHG governance, policy and standards contracts.
3. Verify that the subject is not already owned by another canonical document.
4. Define the local Foundation scope and specialization.
5. Use the canonical metadata and relationship vocabulary adopted by BHG Governance.
6. Create and validate the document on a non-main branch.
7. Record cross-repository impact where applicable.

## Repository boundary

This repository may define:

- institutional architecture;
- ecosystem architecture;
- organizational architecture within its approved scope;
- repository ecosystem relationships.

It must not redefine:

- constitutional authority;
- global document metadata semantics;
- global document relationship semantics;
- product-specific implementation rules;
- governance approval mechanics owned elsewhere.
