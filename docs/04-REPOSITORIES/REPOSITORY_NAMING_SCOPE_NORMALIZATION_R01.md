# Repository Naming Scope Normalization R01

## Purpose

This record normalizes the scope of the Repository Naming Standard before any repository rename is executed.

## Naming Scope

The `BHG-` institutional prefix is the canonical naming convention for repositories that are formally recognized as BHG institutional repositories and whose classification requires an institutional BHG namespace.

Independent entities and projects retain their own identities unless a separate approved integration or naming decision establishes otherwise.

## Current Application

- `BHG-Governance` — institutional BHG name; preserve.
- `BHG-Ecosystem-Foundation` — institutional BHG name; preserve.
- `bhg-knowledge` — technical name differs from canonical institutional identity `BHG Knowledge`; rename candidate.
- `ZivaLatam` — independent entity identity; preserve.
- `Legalbreto` — independent project identity; preserve.
- `BHG Legal Framework` — planned institutional repository identity; not instantiated through `Legalbreto`.

## Rename Gate

No rename shall occur solely because a name appears in the naming standard.

A rename requires:

1. confirmed institutional identity;
2. cross-repository reference inventory;
3. automation and integration impact analysis;
4. historical name record;
5. governance review and approval;
6. post-rename reference verification.

## Identity Versus Name

Institutional identity and technical repository name are related but distinct concepts.

A canonical institutional identity may exist before a technical rename is executed. This is the current state of `bhg-knowledge`.

## Future Integration Boundary

Future integration intent does not require an independent entity to adopt a `BHG-` repository name.

ZivaLatam therefore remains `ZivaLatam` while it is independent, even though it is architecturally aligned and documented as a future-integration candidate.

## Historical Continuity

Every approved rename shall preserve:

- previous technical name;
- canonical institutional identity;
- rename date;
- reason;
- approval evidence;
- migration and reference verification evidence.

## Authority Boundary

This record does not authorize a rename, establish ownership, or establish subsidiary status.

## Disposition

**R01 — NAMING SCOPE NORMALIZED FOR RENAME IMPACT ANALYSIS.**
